# Assignment 2 — 相机功能恢复版 FullUI 3

## 先说清楚：这个更新解决什么
上一版缺少原相机设置，并把采集固定成320×240。识别结果与JPEG又是分别请求，往往不是同一帧，所以画面有牌但不显示标记不一定等于模型没有检出。本版恢复相机设置、同步显示结果、暴露模型实际输入，帮助区分漏检与显示/测量问题。没有重新训练或替换你的模型，也没有实体相机测试，不能保证模型在所有环境中识别成功。
FOMO定位十字不是停车牌完整轮廓。本版只有匹配的红色区域通过基本尺寸检查才绘制测量框；仍是颜色区域的估计，不是完整八边形分割。遮挡、阴影、反光、红色背景仍可能影响测量。

## 连接的是谁？为什么可以控制UNO？
连接的Wi-Fi由ESP32提供。手机网页 -> ESP32 -> Serial2串口(RX33/TX4，9600) -> UNO执行电机/舵机/灯光控制。
依据你提供的 Implementation principle of SmartRobot Car.pdf，UNO拥有Motor、Servo、Ultrasonic、Itr20001、RGB LED等设备驱动；ESP32负责Camera及Wi-Fi。你的Assignment1原始ino本来就有WiFiServer(100)和Serial2转发。
本版主界面是摄像头；小车功能放入独立“UNO controls”页面。无新鲜UNO遥测时禁用车控区，不影响相机工作。要用车控必须运行此前Assignment2 UNO程序；原厂UNO程序不一定支持这些扩展命令。

## 分辨率到底改变什么
Resolution改变传感器输出的真实JPEG尺寸，不只是CSS放大。预览上方Photo显示原照片尺寸，analysis显示像素测量使用的尺寸。
ESP32的内存无法无条件容纳1600×1200×3的RGB数组。本版使用JPEG分级解码，分析图宽高均不超过400；不裁掉两侧。模型仍是导出时固定的96×96，不能在网页把模型改成800×600。
典型对应：QVGA分析320×240；CIF400×296；VGA320×240；SVGA400×300；XGA256×192；SXGA320×256；UXGA400×300。
因此UXGA更清晰的原照片不等于更强的AI输入。排查识别先用QVGA或SVGA，保持牌子完整，检查96×96输入。
相机设置不写Flash，重启恢复默认QVGA/自动白平衡。距离标定是单独的持久数据。

## 先诊断停车牌，再标定距离
1. Camera选QVGA，关闭人脸功能(只为先单独测试停车牌；并非程序强制互斥)，打开STOP AI。
2. Detection -> Model view默认Centre crop，与导出模型的FIT_SHORTEST一致。蓝色虚线框内才送给模型；把完整牌面放进去。
3. 点击Refresh input。它是程序实际送入模型的96×96图像，以最近一帧的BMP提供，标明帧号。若在这里已模糊或牌子被裁掉，先调整位置/光照。
4. 牌子较小时选Movable crop 2×，点预览中的停车牌，把区域移动过去；必须留下完整牌面及少量背景。4×仅用于更小目标，不能恢复原图已经缺失的细节。
5. 要覆盖左右边缘可选Full frame letterbox；它保留整幅画面并填黑边，与训练的中心裁剪方式不同，实际效果需要比较。默认仍为原训练预处理。
6. 黄色十字+STOP分数表示模型检出位置；绿色框表示另行测量的红色区域。只有十字时可以识别成功但没有可用尺寸，此时不要标定距离。
7. Highest returned score显示模型返回的最高分；80%是默认显示门槛。导出库本身丢弃50%以下结果，因此“<50% / none”不代表能读取到每个更低分。可暂时调低到60%观察候选，但可能增加误检；UNO已有停车保护仍要求80%。
8. 如果实际输入清晰、牌面完整、颜色正确，仍长期无候选：保存Save model input及Save full photo。前者用于诊断；后者用于重新标注/补充训练。此时才考虑加入小车实际视角、距离、背景、无牌场景数据并重新训练。UI修改不能替代模型泛化能力。
9. AI error非0是推理执行失败，与“没有识别出停车牌”不同；去Diagnostics复制JSON及ESP32串口115200日志。

## 测距
仍然使用匹配红色区域宽度，只对基本合理的区域估算；FOMO自身框只用来定位。
新版K采用归一化宽度：K=已知距离×(区域宽度/分析图宽度)，距离=K/(当前区域宽度/分析图宽度)。更改采集分辨率会改变传感器视野/采样，故标定同时绑定分辨率；不会默默套用另一个分辨率的数据。
本版用新存储命名空间a2-cam-v2，避免误读旧版像素单位K。首次更新需重新标定一次。成功保存后同分辨率重启仍保留；当前存储仅保留最近标定的一个分辨率下五类目标参数，切到其他分辨率先显示未标定，在新分辨率保存会替换旧分辨率参数。
标定：Measurements选stop -> Sample selected object width -> 填尺子量得的镜头到停车牌平面距离 -> Save calibration。设置改变会要求重新采样；仅重启不必重新标定，但要选择与保存时相同的分辨率。
更换打印大小、镜头、实际目标后仍需重新标定。不要用超声波距离替代小停车牌的已知距离。
新测量框增加宽高比/区域面积/边缘检查，但不是可靠的完整牌面证明；需要实测误差。发现轮廓不完整时不要依据该尺寸标定。

## UNO及原APP
保留手动8方向/停止、速度、IR循迹、超声波避障/跟随、AI停车+循迹、停车保护与复位、舵机、RGB灯、传感器遥测。原APP TCP100转发保留。
UNO controls里的超声波数据只是探头方向上的距离，不标成停车牌距离。
改变相机/分析设置会先发送停车指令，随后按需手动恢复驾驶。人脸与STOP同时运行会增加处理延迟，原UNO数据超时保护保持不变，可能拒绝过慢的结果，不建议以放宽超时代替性能排查。
本版最多显示4个STOP与4个颜色区域；向UNO发送其中优先满足80%置信度、未知距离或更近的STOP结果。停车逻辑其余不改。
