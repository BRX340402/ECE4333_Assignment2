# V2 串口及网络协议

## 物理与封装

板间9600 baud、8N1，ESP32 RX33/TX4，UNO硬串口D0/D1，经原车Cam连接电路。ESP32 USB调试为115200。两套固件必须一起更新，不与旧版协议混用。
每帧一个扁平JSON对象，发送端追加换行；接收端以花括号识别，可接受APP不带换行。UNO接收最大191字符，不支持嵌套对象/字符串内花括号。无CRC；JSON结构、数值范围、视觉序号和超时提供基本过滤，不是安全认证协议。

## 视觉结果：ESP32 → UNO

```json
{"N":200,"S":100,"A":1,"V":1,"P":920,"R":25,"X":160,"Y":120,"W":45,"H":48}
```

|字段|含义/范围|
|---|---|
|S|16位帧序号0…65535，允许回绕；新鲜期内丢弃重复或倒退|
|A|模型已启用且AI检测开启，0或1；颜色显示开关不影响FOMO|
|V|该帧有效，发送时距采集≤2000ms，0或1|
|P|最高stop置信度×1000；未发现stop为0|
|R|距离cm，未标定/边界截断为-1；有效0…10000|
|X/Y|中心像素，范围0…319/0…239；无stop为-1|
|W/H|框尺寸，范围0…320/0…240；无stop为0|

这是单个最佳stop结果，不是全框数组。其他颜色框可从ESP32 USB JSON或HTTP /results获取。没有模型的颜色红框不会被当作停车标志发送。

## 控制命令

|N|D字段|操作|
|---|---|---|
|100或110|无|待机停车|
|101|D1=0…4|模式：待机/巡线/避障/距离跟随/AI巡线|
|102|D1=1…9，D2可选0…180|前/后/左转/右转/左前/左后/右前/右后/停车；D2速度|
|103|无|远程心跳，不自行启动电机|
|104|D1=0…180|设置PWM速度|
|5|D1=1,D2=0…180|停车后转动水平舵机|
|106|D1=1/3/5|停车后舵机左15/右15/中90|
|8|D1选择器，D2/D3/D4=R/G/B|设置单颗灯，颜色0…255；本版忽略选择器|
|105|D1=1/2|亮度增加/减少5，上限100|
|201|D1=0/1|先停车，再关闭/开启AI guard，开启需有效AI|
|202|无|先停车，再尝试复位stop锁定|
|21/22/210|无|请求统一N210遥测|

部分操作返回{"N":211,"OK":1}，拒绝为OK=0；快速连续命令可能合并应答。视觉包、方向、心跳不逐包应答。它不是带命令ID的可靠确认机制，应读取遥测确认实际状态。原APP专有传感器响应和图形积木命令未全覆盖。

## UNO → ESP32遥测

约1秒一个N210，非阻塞分段写入串口。字段：M模式，B状态原因，G guard，T停车锁定，U超声波cm（-1无回波），L/C/R地面左中右ADC，V估算电池mV，S舵机角，Q最近视觉序号，A/D左右轮有符号PWM。
B：0待机，1运行，2远程超时，3AI缺失或过期，4失线，5停车锁定，8超声波无效或超出跟随距离。2/3为事件状态，随后待机帧可恢复为0，不是历史故障日志。

## 网络

ESP32 AP：ECE4333_A2_V2，密码12345678。
- GET /：网页；POST /cmd：表单动作（见WebPage.h）。
- GET /results：最近视觉JSON加UNO状态、数据年龄。
- GET /capture：当前JPEG；可带seq，改变则409。
- GET /sample?i=0：指定目标的96×96调试预览BMP；它不是FOMO训练用的全图标注；响应X-Frame-Seq。
- TCP100：原APP扁平JSON转发；{Heartbeat}维护连接；3秒APP无消息断开，其运动另由UNO1.8秒超时约束。
- HTTP81 /stream：MJPEG。原APP实际视频兼容性待对应版本验证。

请只用一个控制客户端操作。多浏览器没有独占控制身份，多端同时发送动作会互相覆盖。
